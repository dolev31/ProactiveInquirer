# Decisions a human had to make

Each of these is a judgement call that the code silently depends on. Written down with a
named default so that a reviewer can see it was decided rather than defaulted, and so that
changing one is a visible edit rather than a quiet drift.

| # | Decision | Default taken | Why, and what it costs |
|---|---|---|---|
| D1 | **Depth semantics** for prerequisite edges | **AND** (`1 + max(parents)`, longest path) | A prerequisite means "all of these first". Shortest-path BFS understates depth at every multi-parent node, dragging deep needs into shallow buckets and blurring the depth-1 ablation. OR is retained and both are reported. |
| D2 | **Node atomicity** | paragraph (MuSiQue/2Wiki/StrategyQA), whole document (τ²), aggregated key point (DRGym) | Node count drives RNR and every coverage number. Fixed per suite, recorded in the graph pin, and the θ sweep ships so elasticity is visible. |
| D3 | **Entailment threshold θ** | 0.85, swept over {0.60, 0.75, 0.85, 0.95} | The sign of the primary contrast must be stable over [0.75, 0.95] or no claim is made. |
| D4 | **Discoverability threshold** | per-document token overlap ≥ 0.60 | The n-gram containment rule measured **98.2%** user-private on real τ² data and swung **38 points** across n=2..5. That number is the Inquirer's ceiling, so the instrument cannot be a free parameter. The elasticity curve ships with every ceiling number. |
| D5 | **Seed set (depth-0)** | entity coverage ≥ 0.99, with early-resolve ≥ 0.80 as a *flagged* fallback | Move one node in or out and every depth downstream shifts. The share admitted by the weaker basis is reported next to every depth table. |
| D6 | **Success threshold for the mining pool** | τ² reward = 1.0; MuSiQue/2Wiki F1 ≥ 0.9; DRGym KPR > p75 of `drafter_only` | Preregistered, not tuned after seeing the graphs. |
| D7 | **Who adjudicates** | the author, reading 30 sampled trajectories per sweep | No external raters are budgeted. Stated as a limitation. Every metric here can be satisfied by a policy that asks nothing useful; only human reading catches that. |
| D8 | **Seeds** | S=1 with common random numbers across arms; S=3 on a 25% subsample | Cost to fixed power scales as `n·S`, so seeds are the most expensive way to buy power. The subsample exists only to estimate `σ_seed`. |
| D9 | **May `dev-` runs appear in the paper?** | **No** — mechanically excluded by the aggregator | A dirty tree means the code that produced the number is not recoverable. |
| D10 | **What if all three judge families fail position bias?** | Report the failure as a finding about the instrument; fall back to the judge-free endpoints (τ² reward, MuSiQue F1) and drop the DRGym primary | An unusable judge is a fact about measurement, not a reason to pick the least-bad one. |
| D11 | **Which suites may never be trained on** | **τ², PARE and UserBench. Never.** `EVAL_ONLY_SUITES` refuses them at the exporter, and `split_of` returns `test` for every one of their tasks | 97 tasks is too few to split, and zero-shot transfer to an action-consequential environment is a far stronger claim than a within-suite gain. UserBench joined on 2026-09-02 for the same reason plus one of its own: it is the only benchmark here that this project did not build, so it is the one number a reviewer can check against someone else's ruler, and training on it would spend that for nothing. This row said "τ² and PARE" while the constant held three suites — `pi suites audit` is what catches the code drifting, and nothing catches a decision log drifting except reading it. |
| D12 | **Below-noise-floor effects** | printed as a `below_noise_floor` column plus a render-time banner — never an exception | A linter that throws at 2am gets disabled, and then the guard is gone entirely. |
| D13 | **Retrieval variant for τ²** | `bm25` (offline, dependency-free) | `alltools` raises at construction without `OPENAI_API_KEY` + sandbox-runtime, which would make results unreproducible for anyone else. |
| D14 | **Corpus for DRGym** | FineWeb only | ClueWeb22 needs a signed institutional licence with weeks of lead time. The `corpus` parameter stays swappable. |
| D15 | **May the Inquirer address the user?** | Open `Ask.target="user"` for `convlog` ONLY; every confirmatory arm keeps `allow_user_target=False` | In a Claude Code session the channel *was* open, so a state rendered without it misdescribes the decision the agent actually faced. Opening it globally would break the confirmatory arms, where a user-targeted ask is a bug alarm (`rejected_user_asks`) and the placebo fragment holds prompt length constant. |
| D16 | **Is the convlog suite released?** | **No.** Derived labels keyed by `item_id`, with no transcript text, at most | The text is a collaborator's private work, carries third-party names, and no licence covers redistributing it. Releasing labels alone keeps the measurement auditable without republishing anyone's conversation. |
| D17 | **What the scrubber leaves alone** | bare `@handles` and SLURM job ids | `@leshem.choshen` and `@pytest.mark.parametrize` are one regex, and these states are full of code; redacting every `@name` corrupts the corpus on every decorator. A 7-digit integer is a job id, a line number and a byte count. Both are residual risks accepted because the corpus is never released and Gate A reads it. |
| D18 | **May the private Atlas show convlog rows?** | **Yes**, on the owner's explicit request, with a do-not-share banner on the page | D16 governs RELEASE, not a page private to the person whose conversations these are. Every string passes the fail-closed scrubber at parse time and is re-checked at build time, where a hit REFUSES rather than reports. The cost is real: the artifact now carries transcript text, so sharing it would distribute what D16 withholds. |
| D19 | **Is the caller's unit order an input to a BCa interval?** | **No** -- `cluster_bootstrap` canonicalises its input: units sorted, and the values within each unit sorted | Resampling draws unit INDICES, so the same units in a different order returned a different interval, and no record stated which order it used. Canonicalising only the outer list would leave the same defect one level down, because reordering values inside a cluster changes that cluster's sort key. `pinq_train.gate.bca_ci` replicates it, contract 3 forbidding the import. The cost is that recorded endpoints moved: no interval changed which side of zero it sits on, and no point estimate moved at all, a mean over clusters being order-invariant. |
